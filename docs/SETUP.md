# 設置と動作確認

## ローカルで確認

Node.js 26以降で実行します。

```sh
npm ci
npm test
npm start
```

`http://127.0.0.1:4180` を開きます。ローカル版の回答はブラウザ内だけに保存されます。テストは模擬のシートと生成データを使用し、Googleの回答表には接続しません。

## Google Apps Scriptに設置

1. `npm run build` を実行します。
2. Google Apps Scriptで新規プロジェクトを作り、`apps-script/` の `Code.gs`、`Core.gs`、`DemoBank.gs`、`Index.html` を同名で配置します。同じコードを複数ファイルに重複して配置しないでください。
3. プロジェクト設定でマニフェストを表示し、`appsscript.json` を反映します。
4. `doGet` を実行し、Googleの認可を完了します。設定・回答用スプレッドシートが作成され、実行ログにリンクが表示されます。
5. 「デプロイ → 新しいデプロイ → ウェブアプリ」で設置します。実行ユーザーは管理者、アクセス範囲は対象者に合わせて設定します。
6. 発行された `/exec` のURLを回答者に共有します。

シートIDはスクリプトプロパティ `STUDY_108_SHEET_ID` に保存されます。公開コードには実際のIDやURLを記入しません。以後の `doGet` は同じ表を利用します。

## 設定と更新

- `Stimuli`：本文と条件。54条件に各1件または各2件、合計54件または108件を登録します。各参加者には各条件1件ずつ、54件を提示します。
- `Questions`：題干、選択肢、使用有無、`type`（binary / likert7）、`block`（Q1 / Q2）。Q1は先頭固定、Q2の順序は参加者ごとにランダム化し、その参加者内では維持します。
- `Settings`：タイトル、開始説明、受付状態、記録用のdemoフラグ。

シートの変更は新しい作答に反映します。開始済みの作答では開始時の本文・質問・順序を維持します。新しい作答の確認には別のブラウザプロファイルなどを使用してください。試用ラベルと再開始ボタンは画面に表示しません。

画面の固定文言は `src/app.js` と `src/index.html` で変更します。変更後にビルドしてApps Scriptのファイルへ反映し、「デプロイを管理 → 編集 → 新バージョン → デプロイ」で既存URLを更新します。エディタで保存するだけでは公開版は更新されません。

既存の旧108件版の表を使う場合、初回アクセスで質問表を `Questions_previous` に控えてから新しい4問へ更新し、`Participants` と `Analysis` を追加します。原始回答と既存セッションは保持します。27件版のプロパティ `STUDY_SHEET_ID` からは自動移行しません。

## 回答データ

| シート | 内容 |
|---|---|
| Sessions | 作答中の回答、本文・質問のスナップショット、再開用トークン |
| Responses | 提出済みの原始回答。54件×4問で1人216行 |
| Participants | 短縮IDと元IDの対応、性別、その他の自由記述、版 |
| Analysis | participant_id、stimulus_id、question_id、rating、version、genderの6列 |

Q1は1＝読みたい、0＝読みたくない。Q2は1〜7です。Analysisは提出時に更新する派生表で、原始記録を残します。以前の回答で性別が未取得なら空欄です。

回答はブラウザに下書きを保存して即時に画面を進め、バックグラウンドで順次同期します。最終提出と「保存して休憩する」はサーバーの確認を待ちます。未同期で閉じた場合は同じブラウザで再開してください。

回答表と再開用トークンは管理者側で管理します。公開リポジトリには回答の書き出し、参加者一覧、認証情報、実際のシート・デプロイ識別子を含めません。
