# 設置と動作確認

## ローカル版

Node.js 26以降を使用します。`npm ci` でテスト用の依存パッケージを入れ、`npm test` を実行してください。ビルドも同時に行われます。

```sh
npm ci
npm test
npm start
```

ブラウザで `http://127.0.0.1:4178` を開きます。右上の「抽出を確認」から条件分布や1,000人のシミュレーションを確認できます。この版はブラウザ内だけで動作します。

## Google Apps Script版

1. `npm run build` で `apps-script/` 内のファイルを生成します。
2. [Google Apps Script](https://script.google.com/) で新規プロジェクトを作り、`Code.gs`、`Core.gs`、`DemoBank.gs`、`Index.html` を同名で追加します。既定の空の `.gs` ファイルは `Code.gs` として利用できます。
3. プロジェクト設定でマニフェストを表示し、`apps-script/appsscript.json` の内容を設定します（V8、日本時間）。
4. 関数 `doGet` を選択して実行し、Googleの認可手続きを完了します。新しい調査用スプレッドシートが作成され、実行ログにリンクが表示されます。同じプロジェクトで再実行しても同じ表を使います。
5. 「デプロイ → 新しいデプロイ → ウェブアプリ」で公開します。「次のユーザーとして実行」は自分を選び、アクセス範囲は対象者に合わせて設定します。学校の管理設定によって選べる範囲が異なるため、対象者側のアカウントでも確認してください。
6. 発行された `/exec` で終わるURLを配布します。公開したコードを変更した場合は、ビルド後のファイルを反映し、デプロイを新しいバージョンへ更新します。

回答用スプレッドシートのIDは、プロジェクトのスクリプトプロパティ `STUDY_SHEET_ID` に保存されます。コードには固定の表IDや認証情報を埋め込んでいません。

Google版では `LockService` によって割り当てと保存を制御します。既存セッションを再利用し、リビジョン番号で古い画面からの上書きを防ぎます。提出時の再試行で回答行を重複させない処理もあります。

## 保存されるシート

| シート | 内容 |
|---|---|
| `Stimuli` | 108篇の本文と条件ラベル |
| `Blocks` | 4人単位の割り当てと乱数の種 |
| `Sessions` | 記事・質問のスナップショット、回答、進行状況、再開用トークン |
| `Responses` | 完了済みの回答。1行が「1人 × 1記事 × 1問」 |

選択内容はまずブラウザ内に保存され、記事を移動する際にサーバーへ保存されます。最後は提出確認を行い、保存完了後に完了画面を表示します。ブラウザの保存データを消したり別の端末に移ったりすると、自動再開はできません。

回答表は管理者用として非公開で管理します。`Sessions` の再開用トークンを含む表全体を参加者に共有しないでください。

## 例文と質問の変更

記事の形式は [demo-stimuli.json](../demo-stimuli.json) を参照してください。

| キー | 内容 |
|---|---|
| `id` | 重複しない半角英数字・ハイフン・下線のID |
| `category` | 金銭 / 不倫 |
| `justice`、`envy`、`sexual` | 大 / 中 / 小 |
| `text` | 日本語の本文 |

27条件それぞれに金銭2篇・不倫2篇が必要です。プログラムは件数とラベルを検証しますが、本文が操作条件に合っているかは研究者が確認します。

Google版では `Stimuli` シートを書き換えます。質問文と両端の表現は `src/core.js` の `QUESTIONS` で変更し、再ビルド・再デプロイします。質問の測定内容を変える場合はIDも変更してください。開始済みセッションは、その開始時の本文と質問を保持します。

最終材料を準備したら `src/Code.gs` の `STUDY_IS_DEMO` を `false` にし、再ビルド・再デプロイします。`DEMO-` で始まるIDが残っている場合、正式モードでの開始を拒否します。研究説明や同意手続きは、この変更だけでは整備されません。

## テストの範囲

`npm test` は抽出アルゴリズム、Apps Scriptサービスの模擬環境、JSDOMでの画面操作を確認します。Googleの実際の権限・配額・同時アクセスや、端末ごとの動作は別途確認が必要です。

参考：[ウェブアプリ](https://developers.google.com/apps-script/guides/web) / [HTMLとサーバーの通信](https://developers.google.com/apps-script/guides/html/communication) / [LockService](https://developers.google.com/apps-script/reference/lock/)
